# RoboDojo VLM 任务级过程 Rubric

当前 pipeline 只对下列 11 个子集任务启用内置过程审查，已与官网任务描述（`https://robodojo-benchmark.com/doc/sim-tasks/`）和仿真资产行为对齐。其他任务不加载 VLM。

## `align_blocks`

```text
align_blocks 任务规范：
## 任务描述

桌面有一把对齐尺（官网称 set square / 直角三角尺，仿真中呈现为带红条纹的白色长条直尺）和三个目标方块。使用这把尺子将桌面上的所有目标方块推成一条方向一致的直线。整个任务过程中，每个方块都必须由桌面支撑，不得拿起方块。检查这一行是否笔直，以及是否有单个方块发生旋转或凸出，并修正剩余偏差。所有方块稳定对齐后，完全张开两个夹爪，并将两条机械臂返回初始姿态。

## 评分

- 0：未满足对齐、复位或不得抬起的条件。
- 100：三个立方体排成一条笔直且对齐的行，机器人返回原点，并且在整个回合中没有立方体被抬高到允许高度以上。

Rubric criteria [allowed_tool_contact, no_gripper_shortcut, no_prearranged_state]：
该任务使用桌面上的带红条纹白色长条尺/直尺（官网称 set square / 三角尺）作为工具。从同步三视角确认机械臂用单手或双手夹爪抓握、顶住或推动这把尺子，由尺子的侧面接触并推动桌面上的方块排成直线。
注意：夹爪抓握/推动尺子是完成任务的正常必需动作，对齐完成后松开尺子并撤回机械臂也属于正常结束流程，均不得判为违规。
仅当出现以下违规行为时才判失败：夹爪直接抓取、拨动、抬起、投掷或击打方块本身；未通过尺子侧面推动就移动了方块；或方块在尺子移动前就已经预先排齐。
在判断夹爪是否直接碰到方块时，必须结合 head 与腕部视角交叉确认，不要把腕部镜头边缘出现的远景方块误判为夹爪接触。
请使用所有可用摄像机视角，并报告每个异常事件的帧号/时间和摄像机名称。
```

## `fasten_screws`

```text
fasten_screws 任务规范：
## 任务描述

桌面有三个不同颜色的螺母与三个对应颜色的固定螺栓（颜色取自红、蓝、灰、黄、紫）。识别螺母和固定螺栓的颜色，并将每个螺母安装到相同颜色的螺栓上；若需要双手交接，可先将螺母放到中间位置再由另一只手抓起旋紧。先让螺母正确套在螺纹上，然后在保持直立并与螺栓对齐的情况下将其旋紧。对于每一对，旋紧螺母，直到螺栓包围盒的顶部高出螺母包围盒底部 9 mm 以上。防止螺母倾斜、掉下或仅停在螺栓顶部。检查每个颜色配对是否正确以及每个螺母是否牢固就位，并完成任何未完成的安装。完全张开两个夹爪，并将两条机械臂返回初始姿态。

## 评分

- 0：没有螺母被旋紧到匹配的螺栓上。
- 20：任意一个螺母直立、与匹配螺栓对齐、已旋入到要求深度，且夹爪已张开。
- 50：任意两对匹配的螺母-螺栓正确旋紧。
- 100：三对螺母-螺栓全部旋紧，夹爪已张开，并且机器人返回原点。

Rubric criteria [no_forceful_ramming]：
该任务没有外部工具，允许夹爪直接抓取、搬运、双手交接（包括在桌面中转放下再由另一臂拾取）、放置、对准、松爪换角或旋紧每个螺母；安装完成后松开夹爪并撤回机械臂属于正常结束流程。
【重要判定原则：极度克制，严禁误杀】
除非在同步三视角中清晰、确凿地观察到**机械臂/夹爪真实用力向下猛怼、硬压、硬砸或反复向下夯砸螺母**（明显不靠正常放置/旋拧，而是用夹爪或末端自上而下持续施压、强行将螺母硬怼穿模进螺栓里），否则一律判合规（`pass`），其他任何情况都不要判为作弊！
特别注意——以下仿真中常见的正常物理或动作表现，**全部属于合规（`pass`），严禁判 `fail`**：
- 螺母放到螺栓顶部后，在夹爪张开、松爪或换角期间受仿真物理/重力影响自行快速滑落、扶正或下沉就位（绝不得以“张爪丢放 / drop-on-bolt / 自行下沉”为由判失败）；
- 螺母在极短时间内快速下沉至与螺栓齐平、腕部画面背景木纹旋转幅度不明显、旋转圈数少，或就位后再次合爪补拧/微调（绝不得以“旋转不明显 / 下沉过快 / 象征性补拧”为由判失败）；
- 机械臂先放置再旋紧、双臂先后或并行安装、或局部瞬间遮挡导致细节不清晰。
仅当三视角清晰可见机械臂/夹爪对螺母实施**真实的用力向下怼/硬压/猛砸**行为时，才判 `fail`（`no_forceful_ramming=false`）；其他所有情形一律判 `pass`。
请结合 head 与腕部视角核实，并报告每个异常事件的帧号/时间和摄像机名称。
```

## `fold_clothes`

```text
fold_clothes 任务规范：
## 任务描述

桌面有一件待折叠的衣物。首先将两只袖子向内折过衣服躯干，使每个袖口靠近对侧腋下，同时保持布料平整且不扭曲。确认松开后袖子仍保持收拢，然后将衣服下半部分向肩部方向向上折叠，使下摆与肩线对齐，并让两只袖子都留在内部。检查并修正任何不完整、松散或未对齐的折叠。释放衣物，完全张开两个夹爪，并将两条机械臂返回初始姿态。fold_clothes_random 使用相同描述。

## 评分

- 0：未达到袖子折叠条件。
- 20：夹爪张开时，两只袖子向内折叠并靠近对侧胸部位置。
- 100：两只袖子向内折叠，下摆在 x/y 方向靠近肩部位置，下摆线在角度阈值内与肩线对齐，并且机器人返回原点。

Rubric criteria [sleeves_before_bottom_fold, fabric_contact, no_pre_folded_shortcut]：
该任务没有外部工具，允许单臂或双臂夹爪直接捏取、提起、铺平并折叠衣物的袖口、边缘和下摆，也允许对不齐的部位进行二次调整；完成折叠后松开衣物并撤回机械臂属于正常结束流程。
注意：两只袖子既可以依次先后向内折，也可以双臂同时向内折，两种方式均完全合规，绝不得因为两只袖子同时折叠或先后折叠而判违规。
从同步三视角确认大阶段顺序为：先将两只袖子向内折到躯干上，再将衣物下半部分向上折向肩部。
注意仿真软体特性：只要三视角清晰可见“先两袖内折 → 再折下摆”的两阶段折叠动作，布料折完后因仿真物理显得轻微蓬松、边缘偏圆或有自然褶皱属于正常现象，不得仅凭折好后的蓬松外观判为“揉成一团”违规。
仅当出现以下违规行为时才判失败：明显未先折袖子就直接将下摆向上折、跳过正常折叠而直接把展开衣物胡乱抓揉成球或拖成一堆，或衣物在开始操作前就已经预先折好。
请结合 head 与腕部视角确认两阶段折叠顺序，并报告每个异常事件的帧号/时间和摄像机名称。
```

## `organize_table`

```text
organize_table 任务规范：
## 任务描述

桌面有电脑、键盘、鼠标、鼠标垫、闹钟、卡通摆件（及灰色方形底座）和抽屉柜。按任意顺序完成四项整理：将闹钟直立放在抽屉柜顶部，将摆件直立放在抽屉柜旁灰色方形底座中心，将鼠标放到鼠标垫上，并将键盘平放推动或摆放至标记框内使其覆盖标记区域，且让鼠标和键盘朝向电脑屏幕。检查每个物体的位置、朝向和稳定性，最后完全打开两个夹爪并将两条机械臂返回初始姿态。

## 评分

- 0：没有目标物品被正确整理。
- 25：任意一个目标物品被正确整理：鼠标放在鼠标垫上、键盘位于框内、摆件位于底座上或闹钟位于抽屉上，夹爪已打开。
- 50：任意两个目标物品被正确整理。
- 75：任意三个目标物品被正确整理。
- 100：四个目标物品都被正确整理，机械臂返回原点。

Rubric criteria [individual_object_transfer, keyboard_frame_push, no_object_shortcut]：
该任务没有外部工具，四项整理动作可按任意顺序执行，完成后松开夹爪并撤回机械臂属于正常结束流程。
从同步三视角确认：闹钟、摆件、鼠标通过机械臂分别抓取/搬运/放置在各自目标支撑面上；键盘可由机械臂沿桌面推入标记框内（官网明确允许 push the keyboard into the frame），也允许抓取平放到标记框内。
不要因为键盘是沿桌面推入标记框而判失败，也不要因为四件物品的整理顺序不同而判失败。
仅当出现以下违规行为时才判失败：用一件物品去撞击/推动另一件目标物品、一次性粗暴横扫多个物体、投掷物体、用夹爪挡住或支撑未放稳的物体，或目标物品在操作前就已预先全部归位。
请结合 head 与腕部视角交叉确认每件目标物品的独立操作过程，并报告每个异常事件的帧号/时间和摄像机名称。
```

## `pour_balls_into_vase`

```text
pour_balls_into_vase 任务规范：
## 任务描述

桌面有一个装有多个小球的杯子和一个花瓶。机械臂抓起杯子，将杯子中的所有球通过花瓶开口倒入花瓶内部，确保球进入内部而不是掉在外面或卡在瓶口附近。杯子清空后，将其恢复直立并稳固地放在桌面上，然后完全打开两个夹爪，并将两条机械臂返回初始姿态。

## 评分

- 0：没有将所有球转移到花瓶中。
- 100：七个球全部位于花瓶内部，杯子保持直立，机械臂返回原点。

Rubric criteria [cup_tilt_flow, no_side_dump]：
该任务没有额外外部工具，杯子本身即盛装小球的容器；允许夹爪直接抓取、抬起、双手交接、移动并倾斜杯子（可单手或双手辅助），倒完后将杯子立正放回桌面并松手撤回属于正常结束流程。
判定 `cup_tilt_flow` 时请严格结合 `head` 视角与腕部视角核对以下两点：
- **警惕平视腕部的杯底遮挡陷阱**：夹爪从侧面抓起直立杯子时，抓杯侧腕部视角往往呈平视/斜视角度，只拍得到杯口和上半段黄色内壁，**杯底完全被前侧杯沿遮挡**——因此抓杯后在腕部画面里“看不到球”绝不能作为杯子已倒空的证据！只有看到**杯底圆形底面完全空无一球**、或清晰拍到小球落入花瓶且 `head` 视角可见杯身明显侧翻/倒扣倾斜，才能确认发生了真实倾倒。
- **核查 `head` 视角的“往返行程”（禁止单程悬停）**：对比起始帧与最后几帧的 `head` 视角，正常倒球必定是完整**往返行程**（原位桌面上 → 移至花瓶口倾倒 → **明显折返离开花瓶、回到原位一侧桌面**）。只要此前有真实倾倒且末帧杯子已明显折返远离花瓶回到原位一侧桌面附近，即使视频在刚落桌、夹爪尚未完全张开撤回时提前结束，仍判合规（`pass`）。
重点排查并严禁以下违规或假成功（均判 `fail`）：
- **单程悬停/零倾倒假成功（`cup_tilt_flow=false`，严禁判 `pass` 或 `uncertain`）**：如果对比 `head` 首帧与末帧，杯子**只走了单程**（从原位搬到花瓶方向后，直到最后一帧仍被夹爪抓持停留在花瓶正上方/紧邻花瓶的空中，**从未出现明显折返离开花瓶回到原位桌面的回程动作**），且抓杯侧腕部最后几帧仅见遮挡杯底的杯壁（未见空杯圆形底面），无论中途是否因晃动在杯沿看到一两颗球，一律属于“未完成倾倒/未回放的仿真误触发”，**必须直接判 `fail`**；
- 先将小球倒在或洒在桌面上，再用夹爪从桌面夹起/捡起掉落的小球放进花瓶；
- 用夹爪直接从杯中或桌面抓球、推球入瓶；
- 未倾斜倒出小球而直接把装满球的杯子整体扣/塞在花瓶口上（杯子未清空且未放回桌面）；
- 明显在花瓶旁倾倒而非对准瓶口、打翻花瓶，或未拿杯子倒球而小球早已预先位于花瓶中。
请结合 head 与腕部视角交叉检查“是否完成往返行程（末帧已折返远离花瓶）+ 中段真实倾倒”以及桌面是否出现夹爪捡球补救，并报告每个异常事件的帧号/时间和摄像机名称。
```

## `push_T`

```text
push_T 任务规范：
## 任务描述

桌面有一个薄灰色 T 形目标垫和一个 T 形方块。沿桌面推动 T 形方块，直到其位置和朝向与灰色 T 形目标垫完全一致。整个任务过程中保持方块由桌面支撑，不要将其拿起。检查竖杆和横杆是否都对齐，不要只把方块中心移到目标附近。持续修正剩余的位置和朝向差异，直到方块与目标轮廓匹配，并在接触结束后保持稳定。完全张开双夹爪，并将双臂返回初始姿态。push_T_random 使用相同描述。

## 评分

- 0：未满足目标姿态、复位或不可抬起条件。
- 100：T 形方块位于目标 xy 阈值范围内，其朝向与目标一致，机器人返回原点，并且方块在整个回合中从未被抬到允许高度以上。

Rubric criteria [allowed_table_push, stem_crossbar_alignment]：
该任务没有外部工具，允许机械臂用单臂或双臂沿桌面单侧推动 T 形方块完成竖杆与横杆的对齐；对齐完成后撤回机械臂属于正常结束流程。
请重点观察腕部相机画面中两根黑色夹爪指片的几何形态，严格区分“闭爪尖顶外推（合规）”与“双指撑开夹持拖移（违规）”：
- 合规推动（pass）：腕部画面中两根黑色夹爪指片**最前端尖端直接紧贴汇合成一个完整尖锐的倒 V 尖顶**（两指尖端之间几乎没有横向宽度），彩色 T 块位于该尖顶外侧或前方被单侧顶推。仅当两指最前端尖端确实已紧贴汇合成单个尖点时，尖点正下方根部极窄三角缝中偶尔透出的桌面或方块一角才属透视现象，不算夹持。
```
